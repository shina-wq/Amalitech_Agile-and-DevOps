# TaskFlow API

A lightweight REST API for creating, organising and tracking tasks, built over two sprints to demonstrate Agile and DevOps practices.

## Overview

| Item | Choice |
|------|--------|
| Runtime | Node.js |
| Framework | Express |
| Testing | Jest + Supertest |
| CI | GitHub Actions |
| Storage | In-memory (no database) |

### Task model

| Field | Type | Notes |
|-------|------|-------|
| `id` | string | Generated by the server |
| `title` | string | Required, non-empty |
| `description` | string | Optional |
| `status` | string | `todo` \| `in-progress` \| `done` (default `todo`) |
| `createdAt` | string | ISO 8601 timestamp |

### Endpoints

| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/tasks` | Create a task |
| `GET` | `/tasks` | List tasks (optional `?status=` filter) |
| `PATCH` | `/tasks/:id/status` | Update a task's status |
| `DELETE` | `/tasks/:id` | Delete a task |
| `GET` | `/health` | Service health check |

### Getting started

```bash
npm install
npm start      # runs on http://localhost:3000
npm test       # runs the test suite
```

### Acceptance criteria

**US1 – Create a task**
- Given a valid `title`, when I `POST /tasks`, then I receive `201` with the task including `id`, `title`, `status: "todo"` and `createdAt`.
- Given an optional `description`, it is saved and returned with the task.
- Given a missing or empty `title`, then I receive `400` with an error message.

**US2 – List all tasks**
- When I `GET /tasks`, then I receive `200` with an array of all tasks.
- Given no tasks exist, then I receive `200` with an empty array.

**US3 – Update a task's status**
- Given an existing task and a valid status (`todo`, `in-progress`, `done`), when I `PATCH /tasks/:id/status`, then I receive `200` with the updated task.
- Given an invalid status, then I receive `400` with an error message.
- Given a task ID that does not exist, then I receive `404`.

**US4 – Delete a task**
- Given an existing task, when I `DELETE /tasks/:id`, then I receive `204` and the task no longer appears in `GET /tasks`.
- Given a task ID that does not exist, then I receive `404`.

**US5 – Filter tasks by status**
- When I `GET /tasks?status=done`, then I receive `200` with only tasks of that status.
- Given an invalid status value, then I receive `400` with an error message.

**US6 – Health endpoint**
- When I `GET /health`, then I receive `200` with `{ "status": "ok" }` and the service uptime.

**US7 – Logging and error handling**
- Every request is logged with method, path, status code and response time.
- Unexpected errors return `500` with a generic message and are logged with details.
- Requests to unknown routes return `404` with an error message.
